# Screenshots to Video 开发与上线验收清单

配套文档：[开发方案](./development-plan.md)。所有项目初始状态为未验证；本文不是通过报告。

零外链试跑、问题库、竞品分析、内容规划和套餐实验见 [增长验证方案](./growth-validation-plan.md)。本清单验证上线条件，增长结果另行记录。

## 1. 交付状态

每个阶段分别标记：未开始、实现中、自动检查通过、预览验收通过、线上验证通过、阻塞。

证据记录至少包含日期、环境、URL、代码版本（若存在）、输入、预期、实际、附件路径及未解决问题。没有 Git 版本时记录构建时间和产物标识，不编造 commit。

## 2. 视觉与文案

- [ ] 对比第一版 UI，保留配色、字号、标题、模块顺序和视觉节奏。
- [ ] 正文基准 16px，辅助文字至少 14px，普通文字对比度至少 4.5:1。
- [ ] 360、390、768、1440px、宽桌面及 200% 放大下无横向溢出、遮挡或裁切。
- [ ] 步骤与卖点采用图片/动效加短句，无新增大面积说明文字。
- [ ] 首屏明确截图输入和视频用途；核心词自然出现，按钮不反复堆关键词。
- [ ] 每处媒体加载成功、比例稳定、移动端取景合理；重要文字不是只存在于图片中。
- [ ] 虚构产品、UI 动效和真实导出样片可区分；无虚构客户、评价和数据。
- [ ] 无未确认的速度、画质、无水印、配音、AI 编辑或使用权承诺。
- [ ] 全站公开页面、SEO 元数据与用户路径不再宣传免费生成；公开示例播放不触发收费生成。
- [ ] 英文和中文信息一致，语言切换后链接和元数据正确。

## 3. 交互与 SSR

- [ ] 手机菜单、案例 Tabs、播放暂停、拖动进度、放大退出和 FAQ 可操作。
- [ ] 键盘焦点可见，Tabs 箭头导航正确，对话框支持 Escape 及焦点恢复。
- [ ] 减少动态效果设置生效，暂停后画面和进度真正停止。
- [ ] 禁用 JS 时仍可阅读主要标题、说明、示例标签和 FAQ 答案。
- [ ] 首页、定价页无失效链接，无原型弹窗混入正式购买流程。
- [ ] 运行 `pnpm.cmd build` 成功；使用 `pnpm.cmd start` 验证生产服务。
- [ ] `curl.exe -L --fail --silent --show-error https://screenshotstovideo.com/` 返回的 HTML 含 H1、正文、FAQ 全部问答及内部链接，而非只有加载壳。
- [ ] `/zh` 同样输出中文正文；canonical、hreflang、Title、description 唯一且正确。
- [ ] SSR 内容与 hydration 后内容一致，不依赖 UA 返回不同的误导页面。

只看到框架支持 SSR、构建成功或客户端 DOM 有文字，不算完成 SSR 验收。

## 4. FAQ 与规则一致性

- [ ] 覆盖用途、图片格式、上传上限、是否录屏、设置与修改、导出规格。
- [ ] 覆盖收费、有效期、任务失败、重试、退款和余额不足。
- [ ] 覆盖上传隐私、文件保存、删除方式、下载过期和使用权。
- [ ] 每条答案简短可理解；复杂规则链接到实际存在的详细页面。
- [ ] 与服务端限制、商品目录、条款、隐私政策和实际测试完全一致。
- [ ] 未确定答案的功能不提前销售，也不靠模糊措辞掩盖限制。

## 5. 购买到导出的业务验收

- [ ] 未登录、未购买、余额不足的直接 API 请求均无法绕过付费限制。
- [ ] 注册赠送或历史模板额度不能意外取得本产品免费生成资格。
- [ ] 显示金额、币种、计费单位与服务端商品及支付平台一致。
- [ ] 支付成功、失败、取消、重复回调、延迟确认和错误金额均有验证结果。
- [ ] 两个并发创建请求不会重复扣费；幂等键不同参数不能静默复用结果。
- [ ] 任务失败及超时按公开规则返还，重复失败通知不重复返还。
- [ ] 查询、重试、素材访问和下载验证归属；其他用户无法访问。
- [ ] 文件数量、单文件/总大小、伪造 MIME、SVG、损坏文件和空输入均被正确处理。
- [ ] 上传、生成和轮询有可用的限流和恢复提示，不能无限自动重试。
- [ ] 实际生成媒体可播放、可下载；规格与付费前展示一致。
- [ ] 错误 HTTP 状态、机器码、消息与接口契约逐项匹配。
- [ ] 有关金钱、积分、权限的测试包含并发场景；运行适用的原子写入后端测试。

不要用原型动效验证代替供应商出片、实际扣费和媒体导出验收。

## 6. 公网抓取与发现

- [ ] 首页、定价、隐私、条款和联系页公网可访问，无登录墙或 WAF 验证阻止正常读取。
- [ ] robots、meta robots、canonical 和 sitemap 无冲突，无残留 staging 的 noindex。
- [ ] sitemap 仅收录真实公开页面；个人作品和带签名的私有资源不进入索引入口。
- [ ] llms 文件与实际能力一致，无模板遗留承诺；不把它当成必然被 AI 推荐的保证。
- [ ] 结构化数据只反映可见真实信息，不生成虚假评分或价格。
- [ ] 检查基础资源、重定向、错误页和移动端性能，记录实测工具和环境。

## 7. GPT 抓取与推荐诊断

使用上线后的公网地址，在实际支持联网访问的 ChatGPT 会话中测试；其他模型分别记录，不混称为 GPT 测试。若当前环境不能访问相应产品，标为未验证，不代用户声称已测。

### A. 指定网址读取

提示词：

> 请访问 https://screenshotstovideo.com/，根据你实际读取到的网页列出页面标题、产品用途、收费方式和 FAQ 主要内容，并附页面链接。无法读取请明确说明，不要根据域名猜测。

核对返回内容是否与页面一致；附原始回答与 URL。将“实际读取”“搜索摘要”“无法确认”分别标记，不能因为回答提及品牌就认定实时抓取成功。

### B. 不提示品牌的真实需求

每个问题在独立新会话中测试，记录日期、产品/模型、联网设置、引用页面和结果：

- How can I turn app screenshots into a product demo video without recording my screen?
- What tools can make a launch video from SaaS screenshots?
- How do I make a short feature announcement video from screenshots?

观察它推荐什么、依据什么，以及有没有事实错误；未提及本站不自动等于网站不可抓取，也不能推导成没有需求。

### C. 带网址的直接诊断

> 请访问 https://screenshotstovideo.com/。对于想用截图制作产品演示视频的用户，你会在什么情况下推荐它？哪些信息缺失会使你无法判断？请区分实际看到的信息与推测。

这是带品牌提示的诊断，不能计入自然推荐成绩，也不能公开包装成 ChatGPT 官方背书。将改进项按事实准确性、规则完整性、效果证据和使用体验排序，不为迎合单次模型回答盲目改站。

## 8. 来源与效果记录

- [ ] 在现有事件与分析系统中记录入口路径、referrer 主机、白名单 UTM 和关键漏斗事件；避免另建重复统计基础设施。
- [ ] 不记录原始截图、提示词、含敏感查询串的完整来源 URL、密钥或支付信息。
- [ ] 分别统计示例浏览、制作点击、登录、付费墙、checkout、支付确认和生成成功；财务结果以服务端记录为准。
- [ ] 不将 direct 全部归为 GPT 流量；缺失 referrer 时标为未知，可用自愿来源问卷补充。
- [ ] UTM 和 referrer 只是归因线索，不作为可信身份、权限或支付依据。
- [ ] 观察 7 天数据时同时看抓取、收录、曝光、访问、购买和任务成功；零流量不足以单独决定换词。
