## 供应商规则与重试

2026-11-07 核查 [SeeAPI 退款政策](https://www.seeapi.com/refund-policy/)：系统错误且非用户输入造成的任务失败会自动退供应商积分。已出片但风格不满意不等于系统失败。此政策不是所有失败、拒付、补偿都零成本的保证。

明确失败：释放原预留，重复终态通知不重复返还。未知/超时：保留预留并查询或使用原幂等键恢复同一请求，不以新键自动创建新模型任务。这和“失败后免费重跑一次”不同。

## 数据与付款

- 新表 `screenshot_credit_allocation` 记录一个任务分别用了哪些订单的多少额度；任务状态为非 failed 时均占用。终态失败后无需删除或重复写返还账目，余额查询自动排除该任务的分配。
- 预留任务、校验每笔订单仍已付款、校验剩余额度、插入分配记录全部在同一个 atomic 批次中完成。D1 不使用交互式 transaction。
- 幂等任务 ID 防止客户端重放重复扣费；所有出资订单都参与退款校验，避免跨包消耗后退掉次要订单。
- Stripe 使用现有动态 `price_data`，新商品 ID 区分版本。服务端根据商品目录授权；回调中的 credits 字段不作为授权依据。旧支付会话仍可按旧权益完成。
- 账户接口增加 `remainingCredits`、`legacyRenders`；兼容字段 remainingRenders 仅表示旧次数。通用 AI 积分不参与本功能。

## 可用性

只有筛选后的公共配置可以进边缘缓存，TTL 60 秒。没有用户余额、会话或秘密信息；缓存 key 不携带 Cookie。数据库检查失败返回未知状态 503/no-store，不缓存为“店铺关闭”。页面保留错误与重试提示，同时允许尝试结账；最终由结账服务端验证。
