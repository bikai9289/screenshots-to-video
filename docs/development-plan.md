# Screenshots to Video 开发方案

日期：2026-11-03。域名：`screenshotstovideo.com`。

状态：开发依据。正式实现进展见 [实现状态](./implementation-status.md)；本文原任务清单保留作为完整验收依据，不代表产品已上线或真实生成、支付已验证。

配套文档：[上线验收清单](./launch-checklist.md)、[增长验证方案](./growth-validation-plan.md)。增长方案补充零外链观察、多模型问题库、内容和渠道规划、竞品对标及付费实验。

## 1. 目标与已确定决策

将用户认可的第一版 UI 落地到现有 TanStack Start 项目，建设面向 SaaS 创始人、独立开发者和产品营销人员的付费截图转产品视频工具。

- 第一版 UI 为视觉基准；保留布局、配色、主要标题、动效风格、模块顺序和留白。
- 不做免费生成，不以免费试用、免费额度或无需信用卡吸引注册。
- 首页聚焦 `screenshots to video`，自然解释产品演示、功能更新和发布视频用途。
- 页面以图片、动效和短句交替组织，不新增大段 SEO 正文。
- 正文基准 16px，辅助文字至少 14px；不能靠缩小字体解决溢出。
- 公开核心内容必须 SSR 输出；上线后分别验证公网访问、AI 抓取和推荐诊断。
- 原型、正式实现、自动检查和线上实测的状态分别记录。

## 3. 交付阶段与边界

### 阶段 A：正式首页和文案

交付首页 React 实现、英文和中文消息、素材、响应式、SSR 元数据以及可操作的案例与 FAQ。此阶段不宣称视频生成和支付已经接通。

### 阶段 B：付费制作闭环

先明确生成方式与商业规则，再复用或补齐上传、购买、生成、查询、导出流程。所有实际生成入口都由服务端检查付费资格，前端付费墙不能代替鉴权。

### 阶段 C：上线与实测

在生成和支付验收通过后部署，使用公网 URL 检查 HTML、索引配置、GPT 抓取及真实问题诊断。执行 [上线验收清单](./launch-checklist.md)，保留原始证据。

仅完成 A 可作为预览交付，不能标记为可购买、可生成的正式产品。

## 4. 首页模块与文案约束

| 模块 | 保留内容 | 开发要求 |
| --- | --- | --- |
| 导航 | 品牌、Examples、How it works、Pricing、制作入口 | 真实链接；手机菜单可关闭，键盘可操作 |
| 首屏 | `Screenshots to video.` / `Your product. In motion.` | 双行节奏；一个主 CTA；副标题说清输入输出 |
| 动效展示 | Orbit 截图、播放、进度和放大 | 标注示意；可暂停；尊重减少动态效果偏好 |
| 场景案例 | `Made to make` / `an entrance.`；三个 Tabs | 每次一张主图或一段动效、简短说明；支持键盘切换 |
| 制作流程 | `Your screenshots.` / `A little direction. Action.` | 三步各一张图、短标题和一句说明；文字与真实功能一致 |
| 价值说明 | `Less production.` / `More product.` | 保留三个短卖点，配局部截图或动效，不扩写成长文 |
| 末屏 | `You built it.` / `Now give it a debut.` | 重复主 CTA；付费提示一行；购买措辞依赖真实可用流程 |
| FAQ | `A few good` / `questions.` | 折叠展示，短答案；必要时链接详细规则 |
| 页脚 | `Small screens. Big entrances.` | 示例、隐私、条款和联系入口可访问 |

推荐首屏副标题，按实际容器自然换行，不保证所有屏幕恰好两行：

> Turn product screenshots into demo and launch videos.
>
> Start with your screens. Show what matters.

主 CTA 保留 `Create your video`。示例入口可用 `Explore examples`，无需仅因为它不是客户作品就统一改成更长的按钮。

案例声明采用一句 `Illustrative motion preview. Not customer work.`，放在对应示例附近；不得把 UI 动效标记为真实导出视频。第一版已有示例声明，改稿时统一口径，不重复增加声明块。

不强制每个 H2 出现关键词；在 H1、首屏说明、相关场景正文和 FAQ 自然表达即可。Title 建议 `Screenshots to Video | Product Demos & Launch Videos`。描述必须根据最终交付能力定稿，不写未经验证的速度、格式、授权或画质承诺。

## 5. 图片、排版与可访问性

- 保留第一版黑白底色、荧光绿重点，以及案例区少量辅助色；避免把页面改成另一套模板。
- 图片必须说明输入、输出、步骤或差异；不添加无关照片作为段落分隔。
- 内容节奏为短标题、主要视觉、一句说明、下一模块；说明一般 1–2 句，步骤一句。
- FAQ 每条通常不超过两句；复杂费用、隐私和授权规则转向对应详情页，不能为压缩字数遗漏关键限制。
- 图片设置稳定宽高或比例，提供有意义的 alt；装饰图 alt 为空。
- 重要说明不能只烘焙在图片或视频中，必须同时有可读 HTML。
- 普通文字对比度至少 4.5:1，大号文字至少 3:1；交互目标至少 44px。
- 检查 360、390、768、1440px，另查宽桌面和浏览器放大；无页面横向溢出、遮挡或文字裁切。
- 保留可见焦点、Tabs 键盘导航、按钮名称、折叠状态和对话框焦点管理。
- 长页面可延迟加载非首屏媒体；首屏主体媒体避免因加载策略导致空白。

## 6. FAQ 内容覆盖

采用分类折叠 FAQ，不堆成长段落。首页回答会影响用户购买决定的问题，详细规则提供链接。

| 用户问题 | 必须明确的内容 | 未确定时的处理 |
| --- | --- | --- |
| 能做什么视频 | 支持的实际用途；示例性质 | 仅描述已交付能力 |
| 支持什么图片 | MIME、格式、尺寸和清晰度要求 | 生成适配阶段确定，不先宣传 |
| 能传几张、多大 | 单文件、数量、总大小上限 | 与服务端校验同源 |
| 是否要录屏 | 截图流程与实时交互的差异 | 不宣称截图能复现任意真实操作 |
| 如何控制和修改 | 实际支持的设置、预览和修改范围 | 不虚构聊天修改能力 |
| 导出规格 | 格式、比例、分辨率、时长和水印 | 用可复测的导出结果定稿 |
| 如何收费 | 无免费生成；计费单位、到期与有效期 | 价格与商品目录确认后发布 |
| 失败和重试 | 扣费时点、失败返还、重试是否新收费 | 与任务状态机和支付政策一致 |
| 文件是否安全 | 上传目的、访问控制、保存和删除期限 | 不承诺未实现的本地处理或零保存 |
| 能否商用 | 音乐、素材和视频使用权边界 | 以已确认条款为准，不编造许可或限制 |
| 哪些地方能发布 | 实际导出适用场景 | 不保证应用商店或平台审核通过 |

不机械承诺“所有问题已覆盖”。上线前用产品支持问题清单逐项对照，新增高频问题继续维护。

## 7. SSR、路由和内容架构

- 使用现有 TanStack Start 文件路由，不引入 Next.js 或 React Server Components。
- `src/routes/index.tsx` 保持组合职责；新页面内容写在 `src/blocks/screenshots-to-video/`。
- 可复用展示组件放 `src/components/screenshots-to-video/`，通过 props 获取内容；翻译在 block 读取。
- 双语文案写入 `messages/en.json`、`messages/zh.json`，使用一致的 `landing.screenshots.*` 前缀。
- 使用 Paraglide 的 locale-free 路由和 locale-aware Link，不手工拼接 `/zh`。
- 在 loader 解析 locale，head 输出对应 Title、描述、canonical 和 hreflang，不能为同一页面重复输出冲突元数据。
- H1、模块说明、所有 FAQ 问答、示例说明和内部链接直接存在初始 HTML；折叠 FAQ 不等于延迟请求答案。
- 页面浏览不依赖登录。动画、Tabs、菜单等在 hydration 后增强，禁用 JS 时核心内容仍可读取。
- 不照搬原型的全局 DOM 查询、事件绑定和原生 fetch；React 使用受控状态、effect 清理和现有 typed api-client。
- 后端工作放 API / server function / service，组件不得导入数据库或服务端业务模块。
- 仅为真实独立需求新增页面；不批量创建只替换关键词的同质落地页。

## 8. 付费业务闭环与契约准备

推荐制作路径：浏览示例 → 点击制作 → 登录 → 检查付费资格 → 购买或进入制作页 → 上传和设置 → 确认费用 → 提交任务 → 查询结果 → 导出。

制作页路径暂按 `/studio` 规划，实施前核对现有生成器复用边界；未发布时不能留下失效链接。未登录状态返回登录后恢复目的页，余额不足时保留草稿并引导购买，支付确认前不启动收费任务。

阶段 B 编码前必须完成一份独立接口契约，逐项列出：

1. 创建任务、查询、重试、取消（若支持）和导出的实际方法、路径及认证条件；不假定通用生成接口已经满足需求。
2. 所有字段的必选性、类型、长度、枚举、默认值、示例和客户端/服务端归属。
3. 上传允许 PNG/JPEG/WebP，拒绝 SVG；服务端验证真实内容及所有大小上限；限制值在契约确定后写入共享配置。
4. 任务与媒体归属、任务状态转换、超时、供应商失败、重复回调、轮询退避和下载链接过期处理。
5. 幂等键的作用域、相同键不同参数的拒绝行为，及并发下只建一个任务、只扣一次积分的保证。
6. 金额、积分和商品全部在服务端查目录；使用现有 `atomic()`、claim guard 和唯一约束处理涉及价值的写入。
7. 不给注册或默认赠送积分开生成旁路；明确“拥有余额”和“本产品付费资格”的关系，再决定资格判断规则。
8. 每种异常的 HTTP 状态、专属机器码和双语提示，包括未登录、权限不足、无付费资格、余额不足、非法参数、超限、过期、限流、幂等冲突和上游失败。
9. 现有 envelope 的兼容策略；不能为新功能改变所有接口的 code=-1 行为，也不能把 HTTP 200 的业务失败当作成功。
10. 失败返还与重试收费规则、日志脱敏、按 IP 及登录用户分别限流；写入涉及用户的事件应在 API 层协调。

此处是契约交付要求，不是已定义的 OpenAPI，也未调用 OpenSpec 工作流。若后续使用 OpenSpec，须按 AGENTS.md 的八项完整性规则全量检测，失败时给报告和修复方案。

## 9. 开发任务顺序

以下任务在当前会话内顺序执行即可，不默认创建子代理，不自动提交代码。

- [ ] A1：核对 `index.html`、`styles.css`、`copy-v2.html`，建立首屏、案例和手机端截图基线；保留原型文件。
- [ ] A2：在 `src/blocks/screenshots-to-video/` 和 `src/components/screenshots-to-video/` 实现模块，素材迁移到 `public/imgs/screenshots-to-video/`。
- [ ] A3：将 `src/routes/index.tsx` 替换为新模块组合；补齐双语文案和页面元数据；不修改无关管理后台。
- [ ] A4：实现菜单、示例切换、播放暂停、进度、放大和 FAQ；移除不再适用的模板免费宣传与导航入口。
- [ ] A5：运行 `pnpm.cmd build`，以生产服务验证原始 HTML；执行多尺寸截图、键盘和减少动态效果检查。
- [ ] B1：审查生成、任务、积分、存储、下载和支付现有能力；确定渲染方案及上一节的完整契约。
- [ ] B2：确认商品、成本、资格、退款和保存规则；同步 `src/config/pricing.ts`、定价页及相关配置。
- [ ] B3：实现制作流程与服务端限制，必要时调整 schema；按环境使用开发同步或生产迁移流程。
- [ ] B4：在 `tests/` 增加付费资格、并发扣费、重试、失败返还、鉴权及上传边界测试；先验证失败用例，再完成实现。
- [ ] B5：用真实支付测试模式和实际渲染供应商走通购买至导出，验证输出媒体，清理模板生成旁路。
- [ ] C1：同步 FAQ、隐私、条款、`UPGRADING.md`、robots、sitemap、llms 文件与最终产品能力。
- [ ] C2：部署后执行 [上线验收清单](./launch-checklist.md)，记录公网结果，确认可接受后再标记上线完成。

如果出现生产数据库变更，先生成和审阅迁移，再获用户确认后应用。仅编辑文档不触发迁移、部署或配置修改。

## 10. 上线前决策门槛

| 决策 | 完成判据 | 阻塞范围 |
| --- | --- | --- |
| 视频生成方案 | 真实输入截图可稳定产出可播放视频，明确限制与成本 | 阶段 B 和公开生成承诺 |
| 价格与计费单位 | 服务端商品、展示价格和实际 checkout 一致 | 收费上线 |
| 导出与修改能力 | 有可复测样片与完整参数限制 | 对应卖点和 FAQ |
| 退款与失败返还 | 状态和处理路径可验证，规则公开 | 收费上线 |
| 存储、隐私、使用权 | 与实际基础设施和素材许可一致 | 上传及公开使用权说明 |

经验帖中的 7 天观察期、示例价格和转化率不作为本站已验证事实。7 天只能作为一次观察窗口，不能仅凭零流量判定需求无效；同时检查收录、抓取、曝光和漏斗问题。
